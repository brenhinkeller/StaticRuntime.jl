Entry points

An executable is made of a function, in one of three forms:

formcompile_executable(f, ...)the arguments of the command lineexit statusfile, small = true
main(args::Vector{String})(Vector{String},)args (and ARGS)the integer that it returns, 0 for anything else34.4 kB
main()(), or no typesnone (ARGS is empty)the integer that it returns, 0 for anything else33.6 kB
main(argc::Int, argv::Ptr{Ptr{UInt8}})(Int, Ptr{Ptr{UInt8}})as C has themthe integer that it returns: not defined for anything else33.6 kB

main(args) is the form to use for a program that is written like a Julia script: it has the arguments as ARGS has them, and the status of the program is what it returns if that is an integer (a function that ends with println returns nothing, and exits with 0). main() is the same for a program that takes no arguments. The third form is C's: it compiles f(argc, argv) to the main of a C program, with no code of ours between the two, which is as small as a program can be (the others add a kilobyte or less), and what the examples of the sizes and speeds below use. Its status is the return value as C has it, so the function has to return an Int (or an Int32): for nothing it is whatever the machine had in the register, and the compiler warns of it.

Compilation

See Compiling: overrides, passes, and inference for how it works, and compile_executable or compile_shlib for options and syntax:

main(args) = (println("got ", length(args), " arguments"); length(args))
compile_executable(main, (Vector{String},))    # `./main a b c` prints "got 3 arguments" and exits with 3

hello() = println("hello")
compile_executable(hello)                      # `./hello` prints "hello" and exits with 0

See also: The runtime, Supported libraries and packages, and Limitations.

Testing that something compiles

julia> using StaticRuntime

julia> @static_test sum(rand(10)) < 10     # compile, run, and compare with Julia
Test Passed

julia> static_status(() -> length(string(12345)))
(:ok, "")

static_status reports how far something gets: :compile_error, :link_error, :runtime_error, :mismatch or :ok. undefined_symbols lists what the compiled code needs besides libc.

Overrides

@device_override adds a method to the method table of this package (see below), which replaces the method of Base for the code that is compiled. One key thing to know, if you wish to write your own overrides: an override is used for every call that it covers entirely, instead of all of the methods of Base, including those that are more specific than it. Consequently, an override print(x1, x2) = print(STDOUT, x1, x2) would also be used for print(io, x), which must go to the methods of Base for printing to an IO: print(io, 'c'), print(io, "string")... Overrides therefore need to be written so that they don't cover calls that they should not: with the same signature as the method that they replace, with restricted argument types, or by doing for those calls what the method of Base does (see src/overrides/io.jl).

Stating a type instead of copying code

Many overrides of code from a package are a copy of a function with a type put in it, because the compiler finds a wide type (a Union, Any) where the code knows what it is. A copy drifts when the package changes. @assume states the type, and the code of the package stays as it is:

function __init__()
    StaticRuntime.@assume Makie.theme(::Nothing, ::Symbol)::Attributes   # the call gives an `Attributes`
    StaticRuntime.@assume_field Observable.listeners::Vector{Pair{Int,Any}}  # the field holds this
end
  • The type of a call: @assume f(::A, ::B)::R says that the methods that the arguments A and B (or subtypes) fit give a R. Those methods are inferred as they are, with what they give narrowed to R (the intersection of the two types), and every return of them is a typeassert to R: callers have a type that is right, and a program in which the method gives another type stops with a type error that says so, and does not go on as if it had the type. A function with keyword arguments is stated by its method without them, and a constructor T(...) by Type{T}.
  • The type of a field: @assume_field S.name::T says that a field of the type Any (or another that is not concrete) of the struct S holds a T where it is read, and the read is a typeassert.
  • Both are given where the module is initialized (__init__), as add_dispatch_candidates! is: they are kept for the session, and not by what is precompiled. A package extension is the place. What is stated is a number in the key of what is inferred, so a change of it is a new inference.

Fields that are made again when the program runs

A field of a pointer of a constant (the face of FreeType of a font, a surface of a library) is an address of the process that compiled the program, and is null in the program. A package's extension says how the program makes it again with a method of StaticRuntime.remade_by, which gives a function of the object:

StaticRuntime.remade_by(::Type{FTFont}, ::Val{:ft_ptr}) = font -> open_face(font)   # (from what the font has)

A read of the field (getfield(font, :ft_ptr), wherever the package's code makes it) then makes it, and stores it, the first time that the program finds it null; the warning that the field is null in the program is not given for it. Only fields of a Ptr type. (The extension for Makie does this for the fonts of a figure.)

Running the package tests

] test runs all: the tests of the compiler, the runtime and the language (test/core), as well as those of the standard libraries and the packages that programs use (test/packages). Most of them compile a program and compare what it prints with what Julia prints for the same code. Set GROUP=Core or GROUP=Packages to run one of the two, PACKAGES=Dates,MPI to run some of the files of Packages (the MPI tests need an MPI library, which MPI.jl installs), TEST_TIMING=1 to print the time that each file took, and TEST_FOLDED=0 to not fail the cases whose program is only a print of an answer that the compiler found (which is on by default: the test of such a case does not test the code that it is about) (opaque in test/helpers.jl makes values that the compiler does not know; whether a program computes something from them is read from its module, see StaticRuntime.input_dependent_cases; TEST_FOLDED=report lists those that do not, and goes on). STATIC_RUNTIME_GC=3 runs the programs with the collector in stress mode, sweeping every three allocations.

GROUP=Fuzzing (not part of ] test) runs random values and programs (test/fuzz): each seed is compiled and run in a process of its own, with a time limit, a few at a time, and compared with Julia. The seeds that failed once are run every time (test/fuzz/pinned.jl), with random ones; FUZZ_SEEDS=0x688,1:50 runs the seeds that you give, FUZZ_COUNT is the number of random ones for each kind (20), FUZZ_TIME_LIMIT the seconds for a case (120) and FUZZ_WORKERS how many run at once. A seed that fails or does not finish is written with the command that runs it again by itself: julia --project=test test/fuzz/case.jl embedfuzz 0x688.
