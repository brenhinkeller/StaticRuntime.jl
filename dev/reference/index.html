StaticRuntime.StaticIO — Type
StaticIO{S}

An IO for one of the standard streams of libc, S being :stdin, :stdout or :stderr. There is no buffering besides that of libc (which flushes the streams when the program exits).

These are the streams to use in compiled code instead of stdin, stdout and stderr of Base, which are globals of the abstract type IO, so that calls using them can't be resolved when compiling: STDIN, STDOUT and STDERR. print(x), println(x) and show(x), which write to stdout, do use STDOUT.

Base.open — Method
open(path, [mode = "r"]; read, write, create, truncate, append, lock) -> StaticFile

Open the file path, as a StaticFile. mode is a C fopen mode ("r", "w", "a", "r+", ...: opened with fopen). The keywords are those of Base's open (read = true, append = true, create = false, ...), with the same meaning for each combination: the file is opened with open of the system, with the flags that they say, and then given to libc as a stream (fdopen). lock is accepted and does nothing (there is one thread). Close it with close; open(f, path, ...) does, after calling f(io).

StaticRuntime.add_dispatch_candidates! — Method
add_dispatch_candidates!(types...)

Add concrete types to those that a call on a value of type Any (an element of a Vector{Any}, say), or of an abstract type with too many subtypes to list (Number), dispatches over in compiled code. There are no types that are there to start with: the types that the program itself makes, and the types stored in its containers of Any, are found without this. Use it for a value that reaches such a call from where the compiler does not see (what a C function gives, Base.inferencebarrier, a global of type Any): add_dispatch_candidates!(Int, String). A value of a type that is not listed is an error when the program runs. It is the same list as add_show_candidates!'s, and applies to every later compilation in the process: call it before compiling, not from a package for its own types.

StaticRuntime.add_show_candidates! — Method
add_show_candidates!(types...)

Add concrete types to those that show of a value of an abstract type (an element of a Vector{Any}, say) dispatches over in compiled code, besides the types that the program has (the ones that are stored in a Vector{Any} or a field of an abstract type, those of its own, ...: they are found when compiling): add_show_candidates!(MyType, Tuple{Int,Float64}). It is for a value that comes from where the compiler does not see (what a C function gives, Base.inferencebarrier, a global of type Any), whose type is not known otherwise. A value of another type is an error when the program runs. Call it before compiling. (It is a list, not a method to add, because the dispatch is made in the world age of show_element, where methods defined later are not visible.)

StaticRuntime.allocation_sites — Method
allocation_sites(f, types) -> Int

The number of places in the compiled code of f(types...) that allocate heap memory (arrays, strings, boxed values, exceptions, ...). A program without the collector (see gc in compile_executable) never frees what these places allocate. Zero means the function never allocates. Allocations on paths that never run (a throw that is never reached) are counted too: this is an upper bound.

StaticRuntime.compile_executable — Function
compile_executable(args...; method_table = StaticRuntime.method_table, strict = true, allow = (), kwargs...)

StaticCompiler.compile_executable, using the method table of StaticRuntime by default, and with its runtime (allocation, exceptions, ...) added to the code that is generated.

By default (strict = true) the code is rejected with an UnsupportedCodeError if it contains something that can't work in a standalone binary: calls that need the Julia runtime (most often, dynamic dispatch), or references to Julia objects by their address. strict = false compiles it anyway, with calls that need the runtime aborting the program if they are reached. allow is a collection of names of runtime functions (as in the error message) to accept even in strict mode. A call on a value of Any (or of an abstract type that can't be listed) is made over the registered types (see add_dispatch_candidates!), and compiling says so in a debug message (JULIA_DEBUG=StaticRuntime).

libraries is where a program looks for the libraries that it calls functions of (BigInt, Regex, a JLL, a library of yours): :system (the default) at the path that they have when compiling, or :bundle, in the folder lib next to the program, where they are copied (those that they need as well), and, if they are not there, at that path.

gc says whether the program has a garbage collector. By default (gc = :auto, where the collector is available) it has one if it needs it: a program that allocates only a finite amount of memory in all (nothing that is allocated is in a loop, or in a function that is called from one or that calls itself, or that a library calls; what makes the arguments of the command line, and what is allocated only to stop with an error, are not counted) never frees anything, and has the allocator that does not collect (see Binary size). A library, compile_shlib, can be called any number of times, so there only what is allocated to stop with an error is not counted. gc = true always has the collector: memory that is not used any more is freed (see the section on memory in the manual). gc = false never has it, and never frees memory. A number (gc = 100) is true that also collects every that many allocations and overwrites what it frees, which is for finding bugs in the collector.

optimize = true optimizes the program once more after it is linked (the pipeline O2 of LLVM on the whole program): recursion and allocation can be faster. The program can add up a reduction in @simd (or the elements of a Float16 sum) in another order than Julia does, and so give another result in the last digits. It is false by default.

small = true makes a smaller file, where that can be done without a difference in what the program does: the linker leaves out what the program does not look at (the names of its functions, a segment of constants on macOS).

source
StaticRuntime.compile_executable — Method
compile_executable(f, (Vector{String},), [path], [name]; kwargs...)
compile_executable(f, (), [path], [name]; kwargs...)
compile_executable(f; kwargs...)

Compile an executable that runs f(args), where args are the arguments of the command line, as ARGS is in Julia (they are also available as ARGS), or f(), for a program that takes no arguments (compile_executable(f) is the same; ARGS is empty). If f returns an integer, it is the exit status of the program, and it is 0 if f returns anything else (nothing, for one). This is the convention of Julia's main(args):

function main(args::Vector{String})
    println("Hello, ", isempty(args) ? "world" : args[1], "!")
end
compile_executable(main, (Vector{String},))

The third form of the entry point is C's: compile_executable(f, (Int, Ptr{Ptr{UInt8}})) compiles f(argc, argv) to the main of a C program, with the arguments as C has them. The exit status is then what f returns, which has to be an integer (Int or Int32): for anything else it is not defined.

StaticRuntime.implicated_slot_keys — Method
implicated_slot_keys(c::Compilation, e)

The slots whose types the code that e (an UnsupportedCodeError) is about was inferred with: the slot questions (see depends!) of the methods of its call sites, those on the way from the entry point and those inlined at the call. A failure of a pass with slot types gives up these slots first, rather than all of them: a program can have code that needs the slot types (a field that holds a function, called) and code that the slot types make fail (a branch that is reached with them).

The number that the inference of this pass of the compilation is kept apart by (the parameters of the job: see OverridesParams): a hash of all that it is made with. Each state that inference reads is in it, by what it is, and in a way that is the same in every process (type_hash).

StaticRuntime.input_dependent_cases — Method
input_dependent_cases(mod::LLVM.Module, fs) -> Vector{Bool}

For each of the zero-argument functions fs, whether its code in the module mod (each is a function of its own there: see make_batch_main with isolate) computes something from a value that is only known when the program runs: the time, which opaque in the tests is made of (time_ns() is a call of clock_gettime, which writes into memory), and the entropy of the system (getentropy), which the random numbers start from. Values are followed from what is read of that memory through the instructions that use them, what is stored and read again (in a slot of the stack or an object of the binary, which are told apart, and the rest of memory, which is not), the arguments of the functions that they are given to, and what functions return. A case does if, in the code from which it can still return normally, it stores such a value, returns one, gives one to a call, or branches on one where both ways can return. A case whose function is not in the module (the compiler found what it returns, and the call is gone) does not. It also does if its own code reads memory that is not of its own stack and uses what it reads (a global that is not const, a mutable object that it captured: what is in them is known only when the program runs; a read of a constant is folded by LLVM), calls a function of the program (whose code runs then, whatever its arguments are: print of a number), or uses what a function of a library or of the system gives (stat of a file). A case that does neither is one whose program is only the answer that the compiler found: the test of it tests the compiler's constant folding, and not the code that it is about.

A library, compile_shlib, can be called any number of times, so there only what is allocated to stop with an error is not counted. gc = true always has the collector: memory that is not used any more is freed (see the section on memory in the manual). gc = false never has it, and never frees memory. A number (gc = 100) is true that also collects every that many allocations and overwrites what it frees, which is for finding bugs in the collector.

optimize = true optimizes the program once more after it is linked (the pipeline O2 of LLVM on the whole program): recursion and allocation can be faster. The program can add up a reduction in @simd (or the elements of a Float16 sum) in another order than Julia does, and so give another result in the last digits. It is false by default.

small = true makes a smaller file, where that can be done without a difference in what the program does: the linker leaves out what the program does not look at (the names of its functions, a segment of constants on macOS).

StaticRuntime.static_llvm_module — Function
static_llvm_module(args...; method_table = StaticRuntime.method_table, strict = true, allow = (), kwargs...)

StaticCompiler.static_llvm_module, using the method table of StaticRuntime by default, and with its runtime (allocation, exceptions, ...) added to the code that is generated.

By default (strict = true) the code is rejected with an UnsupportedCodeError if it contains something that can't work in a standalone binary: calls that need the Julia runtime (most often, dynamic dispatch), or references to Julia objects by their address. strict = false compiles it anyway, with calls that need the runtime aborting the program if they are reached. allow is a collection of names of runtime functions (as in the error message) to accept even in strict mode. A call on a value of Any (or of an abstract type that can't be listed) is made over the registered types (see add_dispatch_candidates!), and compiling says so in a debug message (JULIA_DEBUG=StaticRuntime).

libraries is where a program looks for the libraries that it calls functions of (BigInt, Regex, a JLL, a library of yours): :system (the default) at the path that they have when compiling, or :bundle, in the folder lib next to the program, where they are copied (those that they need as well), and, if they are not there, at that path.

StaticRuntime.static_status — Method
static_status(f; kwargs...) -> (status::Symbol, detail)

Classify how far f() gets as a standalone executable: :compile_error, :link_error, :runtime_error, :mismatch or :ok. StaticRuntime.static_status_batch — Method
static_status_batch(fs; inputs = nothing, kwargs...) -> Vector{Tuple{Symbol,String}}

static_status of each zero-argument function in fs, for independent cases. They are compiled as one program that runs them in turn, which is much faster than a program each; any case that is not :ok in it is compiled again on its own, so that each gets the status it would have alone.

With inputs (a Vector{Union{Missing,Bool}} of the length of fs), each element is set to whether that case's program computes anything from a value only known when it runs (see input_dependent_cases), or missing if not known.

StaticRuntime.typed_drawing — Function
drawing = StaticRuntime.typed_drawing(scene; inputs = (), screen_config...)

A drawing of scene (a Makie.Scene, or a Makie.Figure, which is made ready as saving it does: the limits of its axes are those of what they show) with CairoMakie, that the program makes as drawing(path) (an image of the size of the scene, written to path as a PNG) or drawing(screen) (on a CairoMakie.Screen of the scene). The scene is drawn once when this is called, which adds to the graphs of its plots what drawing them needs, and they are then prepared (prepare!, which this calls: call it before this, or not at all); each plot is drawn with the types that it has. Call it before compiling, after the plots are made, and keep it as a constant. inputs are the inputs of the plots that the program changes (typed_inputs, made before this): what is drawn is what the plots are when it is called, with those changes (see typed_node). Plots that are added afterwards are not drawn. The method is in the extension for CairoMakie.

StaticRuntime.typed_node — Function
StaticRuntime.typed_node(graph, key; inputs = nothing)

A node of graph (a ComputePipeline.ComputeGraph, which prepare! was called on, and the graphs that it is connected with) that the program reads as node[], with the types of what it depends on: what the package reads to resolve it (the edges and inputs that it comes from, and the references of their values) is of types that are not known where it is read, those of all the nodes of all the graphs. StaticRuntime.Runtime.UnsupportedCodeError — Type
UnsupportedCodeError

The code that was compiled contains things that cannot work in a standalone binary: calls that need the Julia runtime (such as dynamic dispatch), or references to Julia objects by address. They would crash the program, or abort it if they are reached. Compile with strict = false to allow these (see compile_executable), or allow = (...) to allow specific runtime functions.

Source layout

  • src/method_table.jl: our method table, @device_override and the parameters of our compilations; src/StaticRuntime.jl: the module, compile_executable and the other entry points; src/extensions.jl: the functions that package extensions add methods to; src/registry.jl: what packages register (REGISTRY, which each compilation copies when it starts).
  • src/overrides/: the overlay methods of Base and of the standard libraries, by topic (io.jl, printing.jl, strings.jl, collections.jl, system.jl, bignum.jl, ...).
  • src/inference/: what the compiler does with what Julia's inference leaves to the runtime. The state of a compilation and its keys (compilation.jl), our interpreter (interpreter.jl), the passes and what each reuses from the one before (passes.jl); calls on abstract types (dispatch.jl), tuples (tuples.jl), unknown functions, callbacks and listeners (closures.jl), boxes (boxes.jl), slots of abstract types (slots.jl) and of types (types_as_values.jl), constant objects (objects.jl, object_calls.jl), stated types (assume.jl), @cfunction (cfunctions.jl), replaced calls (redirect.jl), the optimizer's hooks (optimize.jl), and why a program does not infer (diagnostics.jl).
  • src/runtime/: the runtime that is linked into a program: the allocator and collector (heap.jl, heap_link.jl), the objects that are copied into the binary (objects.jl, embedder.jl, constants.jl), types at run time (types.jl), what is refused (strict.jl), and the functions of libraries, BLAS among them (libraries.jl, loader.jl).
  • src/llvm/: our LLVM passes (pipeline.jl, tags.jl); src/testing.jl: static_status and the other functions that compare a compiled program with Julia.
  • ext/: the overlays that need another package or standard library (LinearAlgebra, SparseArrays, Printf, Random, StyledStrings, Mmap, Observables, Makie, CairoMakie, UnicodePlots, MPI, FunctionWrappers).
