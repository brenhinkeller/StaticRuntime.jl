Limitations, testing and reference

Known limitations

What does not work yet, or works differently from Julia, gathered in one place. The sections above say more about each.

Platforms

  • macOS and Linux only for the collector (gc = true, or gc = :auto for a program that needs it); elsewhere it is off by default, and a program that needs it is an error. Linux is tested on CI (x86 and aarch64), not by hand: the collector depends on the layout of the stack and setjmp of the C library, and BLAS on dlopen.
  • The host is the target. The heap and the runtime are made for the machine that compiles, so cross-compiling (a target that is not the host) is not supported.
  • BLAS and LAPACK need LBT and the libraries that back it at the same paths when the program is run (see Linear algebra and BLAS); they are not in the binary. The same is true of any other library that the program calls, unless libraries = :bundle is used (see Libraries: BigInt, BigFloat, Regex, JLLs and libraries of your own); BLAS is not bundled yet.

Refused, because the answer would otherwise differ from Julia's

  • Constant tables hashed by address. A const Dict or Set whose keys are mutable objects (or hold one) with no hash method of their own, and any non-empty IdDict, are made in Julia with the addresses of their keys, which are not the addresses of the copies in the binary: a lookup would quietly find nothing. Compiling such a constant is an error that says so. Define Base.hash (and ==) for the key type, or make the table when the program runs (a table that is made by the program is fine).
  • deepcopy of a type with a package's own deepcopy_internal. The copy here is made field by field, which is not what that method does, so compiling warns, and the program stops if it reaches the copy.
  • Writes that fail. A write, flush or close that libc reports as failed (a full disk, a closed pipe) throws, as in Julia. And if the system has no entropy for the default random number generator, the first rand() throws, rather than the program using a fixed seed (Random.seed! makes one that is meant to be fixed).
  • Loops with @simd (so sum, dot, mean, ...) are vectorized and their reductions reordered, as in Julia, so the results are the same as Julia's, to the last digit, when it is run on the same machine type; other machines (SIMD widths) may differ in the last digits, in Julia as here.

Standard libraries (a survey of them is kept in test/packages, and what does not work, and what happens then, in test/core/limitations.jl)

  • Work: Base64 (base64encode of strings, bytes, numbers, arrays of numbers and what a function writes, base64decode, and Base64EncodePipe and Base64DecodePipe of an IOBuffer), CRC32c, SHA, UUIDs (uuid4() too), Random.RandomDevice, Mmap (Mmap.mmap(path, Vector{T}, dims, offset): the memory is not unmapped before the program ends), Statistics, Random, Printf, Logging (NullLogger), Dates, SparseArrays (with the factorizations), most of LinearAlgebra (exp, sqrt, log and powers of a matrix, eigen, svd, qr, cholesky, lu, schur, ordschur, hessenberg, inv, det, \, opnorm, ...), Sockets' address types, and the file system (see The file system).
  • Do not: Unicode.normalize, graphemes and isequal_normalized (the tables are in libjulia's copy of utf8proc, which is not a library of its own); readdlm / writedlm; @time and @allocated (use @elapsed); TOML.parse (the parser keeps a Module); Markdown.parse is refused when compiling, or stops with a message when it is run (its parser needs Julia's own); Mmap of an open stream, and anonymous ones (only the files that are named by their path are mapped); Test (@test and @testset); with_logger with a logger other than NullLogger; starting other programs; base64encode of several values of different types in one call, and base64encode(f, args...) of a function with arguments.

Tasks, threads and eval

  • Tasks run to their end (see Tasks below): @async, Threads.@spawn, Task, schedule, wait, fetch, yield, @sync, Condition and Channel work, on the one thread, and a task runs when something waits.

  • There is no eval, and no keyword form of invokelatest; @cfunction of a function with captured state (a closure over a variable) does not work (see Callbacks: @cfunction). (Regex, BigInt and BigFloat work: see Libraries: BigInt, BigFloat, Regex, JLLs and libraries of your own.)

  • The heap is not thread-safe. A program, or a library from compile_shlib, allocates from one thread at a time. A library that is called on a stack that is not that of the thread (a task of Julia running on another thread) frees nothing in that call (see Memory and the garbage collector).

What is dynamic

  • Dynamic dispatch is resolved for abstract types with at most 16 concrete subtypes that can be listed, and for Any and the other abstract types over the registered types (see Dynamic dispatch on abstract types and on Any): a value of a type that is not registered aborts the program when it reaches such a call. It is not resolved for types that can't be listed and have no registered subtype (IO). These, Core.Box variables with a type that is not known, non-const globals, splatting a collection whose length is not known when compiling (f(v...)), and calls that compute a type at run time (typejoin, a Dict made from pairs with abstract values, sum(f, v) of a Vector{Any}, isprime) are rejected when compiling (UnsupportedCodeError), or abort the program if compiled with strict = false.

  • Values that are only known at run time (an element of a Vector{Any}) can't be the argument of objectid or hash unless their types are registered, nor === of types and unions, and show of one is limited to the registered types (see show of containers, types and structs).

  • titlecase of a string (it needs the grapheme breaks of utf8proc), the MersenneTwister generator, and Random.seed!(seed) of the default generator need things of libjulia that are not there.

  • Tuples that have a Union as an element (Tuple{Union{Vector{Float64},Vector{ComplexF64}},Int}: what a function returns when the type of one of two values depends on the data) are made by Julia with the types that the values have when the program runs, which an executable can't make. They are fine when the function that makes them is inlined (the tuple is not made), which the compiler favors for them. A tuple that is returned by a function that is not inlined, or that is stored in an array or a Dict, is rejected when compiling; enumerate and zip of a Union of tuples of different types compile, and stop when they are run.

What a binary starts with

  • What the compiling Julia has is copied. A const container, a Ref, a string, ... is in the binary as it was when compiling, and the program changes its own copy (so ARGS is set by the program, from its command line; and a global that the program changes does not change the Julia that compiled it). Only what is of a type that can be reproduced is copied: not a Module, a Task, ...
  • The collector is conservative: it finds references by what looks like an address, so a number can keep an object that is not used, and a reference that is hidden (not in the stack, the registers, the data copied from the compiler, or an object of the heap) is not found. Memory that is allocated with malloc is not looked at (see Memory and the garbage collector). The blocks of small objects are not returned to the system once the heap has them (though they are used again); large objects are.

Differences from Julia when the program runs

  • At most 256 try blocks are active at once (and 256 exceptions being handled): more prints fatal: exception handler stack overflow and exits. An exception that nothing catches prints fatal: uncaught exception (no handler to catch it) and exits with status 1, without a backtrace or the message of the exception.
  • There is no stack overflow check: infinite recursion crashes (segmentation fault) instead of throwing StackOverflowError.
  • Locks do nothing (there is one thread), and islocked is false.
  • Files are libc streams: eachline of a file closes it only when the loop reaches the end (not on break), seek and skip don't report errors, open takes only a C fopen mode, and the keyword arguments of readline and eachline (keep = true) are not supported. The file system (isfile, mkdir, readdir, ...) and sockets are not available.
  • rand without a seed gets its state from the operating system (getentropy); if that fails the first rand() throws, rather than giving the same stream each time. RandomDevice and uuid4() read getentropy at each call.
  • The output is unbuffered beyond libc's: print and println write through FILE*, which libc flushes when the program exits (not if it crashes).

Testing that something compiles

julia> using StaticRuntime

julia> @static_test sum(rand(10)) < 10     # compile, run, and compare with Julia
Test Passed

julia> static_status(() -> length(string(12345)))
(:ok, "")

static_status reports how far something gets: :compile_error, :link_error, :runtime_error, :mismatch or :ok. undefined_symbols lists what the compiled code needs besides libc.

Package internals and testing

Source layout

  • src/overrides/: the overlay methods of Base and of the standard libraries, by topic (show.jl, files.jl, random.jl, bignum.jl, ...); src/overrides.jl is the method table and the entry points (compile_executable and the rest).
  • src/inference/: what the compiler does with calls that Julia does not resolve: dynamic dispatch (dispatch.jl), closures (closures.jl), the slots of abstract types (slots.jl), @cfunction (cfunctions.jl) and the errors that say why a program does not infer (diagnostics.jl). What a compilation finds and is made with, over its passes, is one value that exists for that compilation (compilation.jl); what packages register is the one REGISTRY that a compilation takes a copy of when it starts (src/registry.jl).
  • src/runtime/: the runtime that is linked into a program: the allocator and collector (heap.jl, heap_link.jl), the objects that are copied into the binary (objects.jl, embedder.jl, constants.jl), types at run time (types.jl), what is refused (strict.jl), and BLAS and the loader of libraries.
  • src/pipeline.jl and src/tags.jl: the LLVM passes; src/testing.jl: static_status and the other functions that compare a compiled program with Julia.
  • ext/: the overlays that need another package or standard library (LinearAlgebra, SparseArrays, StyledStrings, Observables, Makie, Mmap, MPI).

Running the tests

] test runs all: the tests of the compiler, the runtime and the language (test/core), as well as those of the standard libraries and the packages that programs use (test/packages). Most of them compile a program and compare what it prints with what Julia prints for the same code. Set GROUP=Core or GROUP=Packages to run one of the two, PACKAGES=Dates,MPI to run some of the files of Packages (the MPI tests need an MPI library, which MPI.jl installs), TEST_TIMING=1 to print the time that each file took, and TEST_FOLDED=1 to fail the cases whose program is only a print of an answer that the compiler found (opaque in test/helpers.jl makes values that it does not know). STATIC_RUNTIME_GC=3 runs the programs with the collector in stress mode, sweeping every three allocations.

GROUP=Fuzzing (not part of ] test) runs random values and programs (test/fuzz): each seed is compiled and run in a process of its own, with a time limit, a few at a time, and compared with Julia. The seeds that failed once are run every time (test/fuzz/pinned.jl), with random ones; FUZZ_SEEDS=0x688,1:50 runs the seeds that you give, FUZZ_COUNT is the number of random ones for each kind (20), FUZZ_TIME_LIMIT the seconds for a case (120) and FUZZ_WORKERS how many run at once. A seed that fails or does not finish is written with the command that runs it again by itself: julia --project=test test/fuzz/case.jl embedfuzz 0x688.

StaticRuntime.add_show_candidates! — Method
add_show_candidates!(types...)

Add concrete types to the ones, besides the usual (numbers, String, Char, Symbol, Nothing, Missing, Vector{Any}), that show of a value of an abstract type (an element of a Vector{Any}, say) dispatches over in compiled code, for example add_show_candidates!(MyType, Tuple{Int,Float64}). StaticRuntime.allocation_sites — Method
allocation_sites(f, types) -> Int

The number of places in the compiled code of f(types...) that allocate heap memory (arrays, strings, boxed values, exceptions, ...). Compiled programs have no garbage collector, so memory allocated at each of these places is never freed: see the section on memory in the manual. Zero means that the function never allocates (that Julia's optimizer removed or put on the stack everything that looked like an allocation).

Calls that don't allocate when they are reached, such as a throw that is never executed, are counted too: this is an upper bound.

StaticRuntime.compile_executable — Function
compile_executable(args...; method_table = StaticRuntime.method_table, strict = true, allow = (), kwargs...)

StaticCompiler.compile_executable, using the method table of StaticRuntime by default, and with its runtime (allocation, exceptions, ...) added to the code that is generated.

By default (strict = true) the code is rejected with an UnsupportedCodeError if it contains something that can't work in a standalone binary: calls that need the Julia runtime (most often, dynamic dispatch), or references to Julia objects by their address. strict = false compiles it anyway, with calls that need the runtime aborting the program if they are reached. allow is a collection of names of runtime functions (as in the error message) to accept even in strict mode. A call on a value of Any (or of an abstract type that can't be listed) is made over the registered types (see add_dispatch_candidates!), and compiling says so in a debug message (JULIA_DEBUG=StaticRuntime).

libraries is where a program looks for the libraries that it calls functions of (BigInt, Regex, a JLL, a library of yours): :system (the default) at the path that they have when compiling, or :bundle, in the folder lib next to the program, where they are copied (those that they need as well), and, if they are not there, at that path.

gc says whether the program has a garbage collector. By default (gc = :auto, where the collector is available) it has one if it needs it: a program that allocates only a finite amount of memory in all (nothing that is allocated is in a loop, or in a function that is called from one or that calls itself, or that a library calls; what makes the arguments of the command line, and what is allocated only to stop with an error, are not counted) never frees anything, and has the allocator that does not collect (see Binary size). A library, compile_shlib, can be called any number of times, so there only what is allocated to stop with an error is not counted. gc = true always has the collector: memory that is not used any more is freed (see the section on memory in the manual). gc = false never has it, and never frees memory. A number (gc = 100) is true that also collects every that many allocations and overwrites what it frees, which is for finding bugs in the collector.

optimize = true optimizes the program once more after it is linked (the pipeline O2 of LLVM on the whole program): recursion and allocation can be faster. The program can add up a reduction in @simd (or the elements of a Float16 sum) in another order than Julia does, and so give another result in the last digits. It is false by default.

small = true makes a smaller file, where that can be done without a difference in what the program does: the linker leaves out what the program does not look at (the names of its functions, a segment of constants on macOS).

source
StaticRuntime.compile_executable — Method
compile_executable(f, (Vector{String},), [path], [name]; kwargs...)
compile_executable(f, (), [path], [name]; kwargs...)
compile_executable(f; kwargs...)

Compile an executable that runs f(args), where args are the arguments of the command line, as ARGS is in Julia (they are also available as ARGS), or f(), for a program that takes no arguments (compile_executable(f) is the same; ARGS is empty). If f returns an integer, it is the exit status of the program, and it is 0 if f returns anything else (nothing, for one). This is the convention of Julia's main(args):

function main(args::Vector{String})
    println("Hello, ", isempty(args) ? "world" : args[1], "!")
end
compile_executable(main, (Vector{String},))

The third form of the entry point is C's: compile_executable(f, (Int, Ptr{Ptr{UInt8}})) compiles f(argc, argv) to the main of a C program, with the arguments as C has them. The exit status is then what f returns, which has to be an integer (Int or Int32): for anything else it is not defined.

StaticRuntime.static_code_typed — Function
static_code_typed(args...; method_table = StaticRuntime.method_table, strict = true, allow = (), kwargs...)

StaticCompiler.static_code_typed, using the method table of StaticRuntime by default, and with its runtime (allocation, exceptions, ...) added to the code that is generated.

By default (strict = true) the code is rejected with an UnsupportedCodeError if it contains something that can't work in a standalone binary: calls that need the Julia runtime (most often, dynamic dispatch), or references to Julia objects by their address. strict = false compiles it anyway, with calls that need the runtime aborting the program if they are reached. allow is a collection of names of runtime functions (as in the error message) to accept even in strict mode. A call on a value of Any (or of an abstract type that can't be listed) is made over the registered types (see add_dispatch_candidates!), and compiling says so in a debug message (JULIA_DEBUG=StaticRuntime).

libraries is where a program looks for the libraries that it calls functions of (BigInt, Regex, a JLL, a library of yours): :system (the default) at the path that they have when compiling, or :bundle, in the folder lib next to the program, where they are copied (those that they need as well), and, if they are not there, at that path.

gc says whether the program has a garbage collector. By default (gc = :auto, where the collector is available) it has one if it needs it: a program that allocates only a finite amount of memory in all (nothing that is allocated is in a loop, or in a function that is called from one or that calls itself, or that a library calls; what makes the arguments of the command line, and what is allocated only to stop with an error, are not counted) never frees anything, and has the allocator that does not collect (see Binary size). A library, compile_shlib, can be called any number of times, so there only what is allocated to stop with an error is not counted. gc = true always has the collector: memory that is not used any more is freed (see the section on memory in the manual). gc = false never has it, and never frees memory. A number (gc = 100) is true that also collects every that many allocations and overwrites what it frees, which is for finding bugs in the collector.

optimize = true optimizes the program once more after it is linked (the pipeline O2 of LLVM on the whole program): recursion and allocation can be faster. The program can add up a reduction in @simd (or the elements of a Float16 sum) in another order than Julia does, and so give another result in the last digits. It is false by default.

small = true makes a smaller file, where that can be done without a difference in what the program does: the linker leaves out what the program does not look at (the names of its functions, a segment of constants on macOS).
